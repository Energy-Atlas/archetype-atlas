# ADR 0029: Explicit physical service 1.2 wire

Status: bounded physical-service core integration under approved Rulings 24-25 and subsequent controller rulings. Public explicit 1.2 generation accepts already qualified legacy recipes. Exact fixture, caller-unit fixed water, recovered bridge and apartment actor production qualifications remain closed; contract fixtures establish structural behavior only. The C6 source science, frozen 1.0/1.1 schemas, releases, and Program JSON v3 remain unchanged.

`params.schema_version: "1.2.0"` alone selects the new request contract. Omission selects 1.0.0. The CLI envelope remains exactly `{schema_version,params,seed}` and its marker must match the effective params version. A 1.2 request always declares `building_realizations`, including `[]`; a 1.2 bundle always retains `metadata.building_realizations` and `generation.physical_unit_seed_sequence`, including `[]`. The latter records the actual selected stock actors and reserves the defined wire for a later separately qualified apartment adapter. Each stock receipt has null building/unit and `generate`; each apartment receipt has both IDs and `generate` or `skip_n0`. Position and unit seed require actual Python integers because JSON Schema also admits integral floats as `integer`; the master seed alone has the unsigned 64-bit limit. Cumulative unit seeds can exceed it. Water-only physical owners create no receipt position.

The request realization union distinguishes an exact-source fixture inventory from a caller-declared apartment unit inventory. Exact-source instances identify an actual role and building realization; caller-unit instances identify a building and actual unit. Legacy whole fixtures retain global physical identity. Physical dedup identity is respectively `(legacy_whole, physical_id)`, `(exact_source_role, building_realization_id, physical_id)`, or `(caller_unit_prototype_density_fixed_dhw, building_realization_id, unit_id, physical_id)`. The full source SID is retained independently for ownership, binding and source-authority checks. A SID cannot manufacture a role, unit, extent, or fixture count.

Strict 1.2 receipt types use `SourceObject` for a complete original object with source path, file SHA-256, locator, and value; `FieldEvidence` for source revision/path/hash/locator, original value/unit, transformation, extraction date, and interpretation; and `Extent` for evidenced source area or absolute one. Original nulls remain null. Source-basis targets retain the original reference schedule budget and units, while whole and aggregate input targets explicitly label their different derivations. No whole target is an independently supplied density.

The independently compiled exact inventory has a complete ordered role list, geometry source object, original service definition, operands, consumed extent, schedule authority, and evidence. The requirement union distinguishes an original programme demand, an original service reference with no invented local demand, and original source components with their own ordered member/source objects. A selected child variant retains the original member/reference and the separately qualified selected method context and adaptation. The caller-unit alternative retains its own original apartment demand, fixed Ruleset, source controls, independently declared unit area/identity and source/reviewed view; it does not borrow exact geometry or commercial HOO.

Every nonphysical 1.2 owner carries both independent requirement inventories and a non-owning projection array, even when empty. The projection union distinguishes programme density, source reference input components, source component density, and caller-unit density. Exact members refer to scoped physical bindings; caller projections refer to one declared actual unit. The composition reference/reason union distinguishes legacy, exact-role, and caller-unit ownership without fabricating cross-branch identities. All new 1.2 objects reject unknown properties; existing opaque 1.0/1.1 source and input payloads remain their prior shapes. The bounded local schema checker vocabulary is unchanged. Public `validate_bundle`, `compose_constituents` and `compare_bundles` validate complete retained authority, references, targets and seed decisions offline without a ResourceSet lookup or production qualification assertion. Public `generate` now replaces the temporary entry guard with independent actual-record preparation and production qualification checks before group/unit RNG. Unqualified new modes still return `requires_binding`; no public flag or shipped fixture certificate enables them.


The 1.2 producer prepares exact-source and caller-unit plans independently, preserves original request encounter order when actual source parents expand, and retains every source allocation and basis-alias receipt. Unknown realization references, cross-mode SID/raw-physical-ID ambiguity, missing owners, incompatible selected group/context and explicit whole-result denominator failures close before seed allocation and sampling. Exact selected executable records come from the independently locked Core3 association, with unchanged original programme views, source inputs and annual authority. Caller water uses Core4's independently locked per-ID fixed-rule pool and evidenced unit declaration. The apartment actor predicate stays false.

Legacy stock keeps the pinned kernel's original finite nonboolean nonnegative numeric resident operand, including source `0.0` and fractional values handled by upstream `to_i`; positive values that truncate to zero reject before stream creation. Apartment cohorts still require exact nonboolean integers. Stock seed positions, full-width cumulative seeds, end-use stream reservation and the 1.0/1.1 path remain unchanged. C5 service-link preparation uses a private copied 1.1 legacy identity view; it never erases exact/caller scope. Incoming C5 physical owners retain their one water load and all original fixed companion controls, with every owned reference checked and unchanged complete-proof equality. Exact/caller owners retain their stricter separately qualified binding contract.

Source-basis B, original extent A/e, whole input W=B*extent, non-owning programme projection denominator, and root composition denominator are distinct. Fixed caller water uses zero draws and retains positive B/W at N0, with derived volume hosted by `building_service`; original unresolved zone-heat evidence and controls remain provenance, with no heater or thermal-energy inference.

An ongoing generated source-parent graph is incomplete until the actual parent is derived and the independent projections are attached. A private generator-only derivation entry consumes the actual prepared allocation, matching verified ResourceSet/RID and emitted ordered children, repeats identity/method/reference/target/area checks, and calls the same extracted mixture arithmetic as public composition. Exact parents derive only local nonwater channels; water remains owned once by the explicit physical owners and projected afterward. Full canonical originals and selected execution proofs remain intact. The complete final graph always passes public validation. Public incoming composition retains its full checks and fresh ResourceSet verification for known-source allocation; no incoming-validation skip flag or generation use of `_incoming` is introduced.
