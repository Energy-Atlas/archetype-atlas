# ADR 0029: Explicit physical service 1.2 wire

Status: bounded structural implementation under approved Rulings 24–25. This ADR records the wire shape, not qualification of an exact fixture inventory, apartment source association, native method, or public 1.2 generation. The C6 source science, frozen 1.0/1.1 schemas, releases, and Program JSON v3 remain unchanged.

`params.schema_version: "1.2.0"` alone selects the new request contract. Omission selects 1.0.0. The CLI envelope remains exactly `{schema_version,params,seed}` and its marker must match the effective params version. A 1.2 request always declares `building_realizations`, including `[]`; a 1.2 bundle always retains `metadata.building_realizations` and `generation.physical_unit_seed_sequence`, including `[]`. The latter is the structural receipt field for a later separately selected stochastic physical-unit adapter. Each stock receipt has null building/unit and `generate`; each apartment receipt has both IDs and `generate` or `skip_n0`. Position and unit seed require actual Python integers because JSON Schema also admits integral floats as `integer`; the master seed alone has the unsigned 64-bit limit. Cumulative unit seeds can exceed it. Water-only physical owners create no receipt position.

The request realization union distinguishes an exact-source fixture inventory from a caller-declared apartment unit inventory. Exact-source instances identify an actual role and building realization; caller-unit instances identify a building and actual unit. Legacy whole fixtures retain global physical identity. Physical dedup identity is respectively `(legacy_whole, physical_id)`, `(exact_source_role, building_realization_id, physical_id)`, or `(caller_unit_prototype_density_fixed_dhw, building_realization_id, unit_id, physical_id)`. The full source SID is retained independently for ownership, binding and source-authority checks. A SID cannot manufacture a role, unit, extent, or fixture count.

Strict 1.2 receipt types use `SourceObject` for a complete original object with source path, file SHA-256, locator, and value; `FieldEvidence` for source revision/path/hash/locator, original value/unit, transformation, extraction date, and interpretation; and `Extent` for evidenced source area or absolute one. Original nulls remain null. Source-basis targets retain the original reference schedule budget and units, while whole and aggregate input targets explicitly label their different derivations. No whole target is an independently supplied density.

The independently compiled exact inventory has a complete ordered role list, geometry source object, original service definition, operands, consumed extent, schedule authority, and evidence. The requirement union distinguishes an original programme demand, an original service reference with no invented local demand, and original source components with their own ordered member/source objects. A selected child variant retains the original member/reference and the separately qualified selected method context and adaptation. The caller-unit alternative retains its own original apartment demand, fixed Ruleset, source controls, independently declared unit area/identity and source/reviewed view; it does not borrow exact geometry or commercial HOO.

Every nonphysical 1.2 owner carries both independent requirement inventories and a non-owning projection array, even when empty. The projection union distinguishes programme density, source reference input components, source component density, and caller-unit density. Exact members refer to scoped physical bindings; caller projections refer to one declared actual unit. The composition reference/reason union distinguishes legacy, exact-role, and caller-unit ownership without fabricating cross-branch identities. All new 1.2 objects reject unknown properties; existing opaque 1.0/1.1 source and input payloads remain their prior shapes. The bounded local schema checker vocabulary is unchanged. Positive-only arithmetic, reference closure, qualification and complete generated graph semantics are later core tasks; these schemas expose the required strict structure without claiming those gates have passed.
