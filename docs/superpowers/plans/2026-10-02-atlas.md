# Energy archetype atlas implementation plan

**Goal:** Produce a reproducible v0.1.0 atlas meeting the governing brief.
**Spec:** `docs/AGENT_RESEARCH_BRIEF.md` (read in full).
**Execution:** Inline and autonomous, as explicitly requested by the user.
**Architecture:** Python tooling consumes checksum-locked official blobs and
emits normalized JSON tables, CSV exports, field provenance, and release hashes.
**Tech stack:** Python 3.11+, unittest, JSON Schema via jsonschema.

## Constraints and review focus

- Original work remains unlicensed; upstream notices travel with derived data.
- Nulls, conditional rules, capacity-dependent efficiencies, and source-specific
  variants cannot become unconditional simulation inputs.
- Stock distributions are evidence, never the canonical deterministic rows.
- Reject checksum drift, ambiguous matches, duplicate keys, orphan references,
  invalid units, physical bounds, and unintended thermostat overlap.
- Source-model overrides can differ from standards tables; compare explicitly.

## Interfaces

`sources/lock.json` -> `scripts/fetch.py` -> `data/raw/<source>/<path>`.
`sources/selection.json` + raw blobs -> `scripts/build.py` -> JSON/CSV atlas.
`schemas/atlas.schema.json` -> `scripts/validate.py` validates all generated data.
`scripts/release.py` consumes validated data and generates an immutable manifest.

## Test sequence

Write real behavioral tests before implementation, observe failures, implement,
then run `python -m unittest discover -s tests -v`. Validate the pilot before full
extraction. Mutation fixtures must fail for the relevant cause. Rebuild into a
temporary directory and compare bytes before freezing a release. Inspect staged
diffs and run `python -m scripts.audit --staged` before every later commit.
