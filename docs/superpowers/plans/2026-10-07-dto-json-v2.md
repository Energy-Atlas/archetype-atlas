# DTO JSON v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver a locally verified current-only catalogue with inspectable linked objects, complete program JSON copying, and interactive schedule inspection.

**Architecture:** Keep the handed-over connector schema fixed. Add a Python exporter and fresh active-site build path over the immutable definition bundle. Share verified lazy JSON between object disclosures, copying and locally served Plotly charts.

**Tech Stack:** Python, JSON Schema 2020-12, MkDocs, plain JavaScript, Plotly cartesian 3.1.0, unittest, Node tests, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-07-dto-json-v2-design.md`; connector contract `docs/program-json-v2-contract.md`.

## Global Constraints

- Work on `feature/dto-json-v2`; no pushes, workflows, merges or publication.
- Keep `schemas/program-json-v2.schema.json` and `schemas/schedule-json-v2.schema.json` unchanged.
- Preserve raw source unknowns and evidence; apply `atlas-program-defaults-1.0.0` only to copied program DTOs.
- Do not manufacture geometry, model sizing or HVAC performance.
- Remove historical routes, downloads and delivery history from active output; retain research inputs and licenses.
- Hourly schedules preserve source rule order, special days and recorded annual year; unknown coverage is a visible gap in raw inspection.
- Every commit needs staged diff inspection and `python -m scripts.audit --staged`.

## Review Focus

- Mixed programs with missing magnitudes retain positive known leaf trajectories and individual heat partitions (Task 1).
- Copying before disclosure, failed resource verification or denied clipboard access never copies incomplete data or reports false success (Task 4).
- Rule precedence, wrapped seasons, leap days and annual year mismatch never silently change a schedule (Task 3).
- Shared service references across mixtures and source leaves never become duplicated local demands (Task 1).
- A new active build cannot import retired routes through cached history, old curated files, navigation or search (Tasks 2 and 5).
