# Offline schedule generator v0.1.0

The [immutable v0.1.0 release](../data/generator-releases/v0.1.0/manifest.json) contains an ordinary independent `generator.zip`. Copy the ZIP and a request JSON to a machine with Python 3.11 or newer. Generation uses only Python's standard library, without Ruby, OpenStudio, EnergyPlus, source downloads or network access:

```powershell
python -I -S generator.zip --request medium-office-request.json --output bundle.json
```

The request is `{ "schema_version": "1.0.0", "params": {...}, "seed": 42 }`. The explicit master seed is an unsigned 64-bit integer; Boolean seeds and unknown fields fail. `params.resource_set_id` must equal the packaged `atlas_schedules/data/manifest.json` resource identity. The `calendar` is `{ "year": 2007, "clock": "local_standard_time", "holidays": [] }`; each hourly value represents `[hour, hour+1)` with no DST or timezone conversion. M1 does not advertise another year, weather/template cross product or holiday overrides. `instances` is ordered and each item names its exact `program_id`, unique `key`, explicit source `inputs`, `basis_bindings`, and nullable `operating_group`. Use the [complete requests and bundles](examples/schedule-generator-v1/README.md) as working examples. The corresponding Python API is `atlas_schedules.generate(params, seed)` and returns the same scientific bundle. The ZIP's root entry point extracts its verified contents into a temporary local directory to make package resources available to Python; it requires no checkout.

The bundle has `schema_version`, `algorithm_version`, `schedules`, `bindings`, `constituents`, `generation`, and `metadata`. Every emitted schedule has 8,760 hourly samples, its unit, calendar and clock. `bindings` link source demands and controls to schedules. Load bindings keep original `reference_target` apart from the realization-conditioned `effective_magnitude`; the latter is the amplitude needed to conserve annual energy or volume, **not** installed capacity. For residential and commercial loads alike, the load-weighted annual integral equals the recorded original/reference annual target after an explicit physical scale. Fraction schedules stay within their valid range. Resident counts, temperatures and other controls keep their defined semantics and are not energy-normalized. Null means unknown, not zero.

Residential seeds follow the source's ordered cumulative unit allocation (for example master 42 gives ordered unit seeds 42, 84, 252), including inactive dwellings. The source HMM, activity/event decisions and coupled appliance streams remain visible as discrete receipts. Commercial operating hours and plug/lighting ratios are sampled once per `operating_group` using the declared conditional seeded adaptation; the group shares that operating sample across coordinated rooms. A null group uses the instance key. The pinned ComStock 0.8.6 / OpenStudio Standards 3.10 rule conversion preserves source rule order, lexical legacy getter, round-five, timestep snap and 15-significant-digit `addValue` storage at the actual source boundary. The source clock is controlled no-DST local standard time; `TZ=UTC` affects only the reference process's month indexing, not physical weather or solar offset. These adaptations are disclosed in the included source/audit resources.

The original residential annual budgets were recovered before fitted amplitudes; commercial budgets were captured before stochastic sampling, base/peak transforms, storage rounding and native export. This is a hybrid of frozen atlas physical definitions/original annual budgets and source stochastic temporal methods. Source family/program and source-versus-reviewed stock/prototype identities remain separate. M1 supplies temporal energy semantics for zoning experiments, not population weights or geometry. The actual upstream population sampling context, including its sampler mode, is unknown; the standalone CLI's available modes do not establish national-realization equivalence.

Mixtures generate their individual constituents first. Normalized weights combine only compatible source bases unless the caller supplies explicit `result_basis`, `denominator` and member physical `extents`, with evidence and units. Supported extents are `floor_area` in m2, `dwelling_unit` in dwelling, `person` in person and `absolute` in 1. A repeated unit's multiplicity must be explicit. No dwelling area, population frequency or geometry is inferred. Thermostat mixtures represent controls across physically active members; original control channels remain attached to their individual owners. Whole shared-service identity requires an explicit physical service binding; an unaudited allocated service remains unsupported.

M1 advertises exactly [ten source-certified cases](../sources/schedule-generator-m1-scope.json): six residential source fixtures, two Office source/reviewed programs and two separate Plenum source/reviewed programs. Eight are active. Both Plenums have source-backed accepted-absence receipts and zero schedules; each still counts toward the ten-case denominator. Their Medium Office sampling configuration association is retained. Every active/fixed/control channel is included. The [coverage report](validation/schedule-generator-coverage.json) lists the remaining 1,890 program and 378 composition identities individually as unsupported or requiring a binding. An outside-scope family request fails clearly. Broader catalogue extraction remains open.

The release manifest pins SHA-256 and byte size for the ZIP and every embedded member, including package-local request/program/bundle schemas, 310 resource records, the resource manifest, source locks, exact M1 scope, complete commercial sampling audit, examples and upstream license notices. Original repository work remains unlicensed by user choice. The ZIP has no raw source archive, development runtime, credential or cache path. A frozen target is immutable; a correction requires a new release version.

```powershell
python -m scripts.schedule_generator_coverage --check --scope m1
python -m scripts.schedule_generator_release --target data/generator-releases/v0.1.0 --verify
python -m scripts.schedule_generator_release --target data/generator-releases/v0.1.0 --reproduce
```

Verification hashes immutable members/resources. Reproduction executes **this release's own embedded runtime and resources** and compares regenerated results against its embedded complete reference: exact source identity, inputs, evidence, RNG/discrete decisions and included channels, with named continuous tolerances from `sources/schedule-generator-policy.json` (fractions `1e-6/1e-8`, temperature °C `0/1e-4`, activity W/person `1e-6/1e-6`, annual energy `1e-8/1e-8`, annual volume m3 `1e-8/1e-12` relative/absolute). Source arithmetic has `1e-8/1e-8`. A three-significant-digit source CSV reference additionally admits its documented quantization interval. JSON formatting, path and `rng.python_version` are administrative; generated JSON/ZIP byte hashes are not a scientific equality test.
